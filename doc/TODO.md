## P1：主要功能与正确性缺口

### 1. 在线调研模式的工具闭环
`research` 在第一轮后无条件停止；真实模型若第一轮只调用分析工具，可能没有第二轮读取工具结果并输出结论。
待办：允许工具调用后再运行一轮，并增加「首轮工具调用、次轮结论」的模拟测试。

### 2. 大工程分析工具缺少分页
`analyze_midi_project` 把完整工程 JSON 交给模型，大工程可能超上下文、高费用或大量内存分配。
待办：按 `trackId`、Tick 范围、游标与数量限制读取，默认只返回摘要。

### 3. 目标模式评估闭环未完成
目标模式有轮次/时间/候选数量限制，但真实 Pi 路径未复用 `GoalRunner` 的成本预算、确定性评分、排序与诊断；
界面候选分数按候选顺序生成，不是模型或确定性评估结果。
待办：统一 Pi 编排与 GoalRunner，或把预算与评估能力迁入 Pi 运行层。

### 4. 工程级候选尚不能在界面应用
MIDI 核心已定义轨道、速度、拍号、循环区操作，但 Renderer 只应用音符插入/更新/删除。
待办：为其余领域操作增加预览、原子应用和撤销支持。

### 5. 候选缺少工程版本绑定
候选生成后工程继续变化时，旧候选可能在语义过期后仍被应用；当前 ID 与数值校验只能阻止结构错误。
待办：请求与候选中加入工程版本或内容哈希，应用前比对。

### 6. 真实云端 Provider 尚未验证
仅自动验证了 Pi 离线 Provider。未用真实 API Key 验证：OpenAI Responses 请求与工具调用、
认证失败/限流/网络错误/60 秒中止、实际 Token/费用/输出质量、在线三模式行为；
ChatGPT Plus/Pro OAuth 已接入并能检测已有 Pi 登录，但未发起真实模型请求验证 entitlement。

### 7. 认证交互仍是最小实现
应用内 Codex OAuth 仅实现浏览器回调登录。尚未提供：device-code 登录界面、浏览器回调失败后的
手动授权码输入、可见的取消按钮与分阶段进度事件、OpenAI 以外的供应商配置界面。
另外 API Key「已配置」仅本地可解析，不代表服务端已验证；后续应提供不泄露凭据的连接测试与错误分类。

### 8. 设置板块后端能力尚未补齐
五板块导航已完成，但以下板块仍是真实状态展示 + 后续入口：
- 通用：主题/外观本地持久化、插件主题贡献目录已预留，但插件发现/安装/授权与主题贡献载入、多设备偏好同步未实现。
- 用量：尚未持久化 Pi 的 Token、费用、模型和按日统计。
- 插件：无插件清单、Manifest、权限模型、安装、启停与隔离执行机制。

在相应后端完成前，界面不得显示伪造的费用、设备或插件数据。（音源板块已完成，见 `INSTRUMENTS.md`。）
